## 目标

实现插件直接调用宿主 LLM 的 canonical API，并默认绕过插件 LLM hooks，避免 hook 内调用 LLM 后递归触发自身 hook。

## 已确认约束

- `hostApi.callLlm` 默认绕过插件 LLM hooks。
- 不提供 `runPluginHooks` 开关。
- 不暴露 AstrBot 风格别名。
- LLM 请求必须走宿主 provider runtime，不允许插件直接使用 provider credential。

## 非目标

- 不实现 streaming；streaming 属于 `T09`。
- 不实现 Agent；Agent 属于 `T11`。
- 不实现 provider 增删改。
- 不让插件读取 API key、base URL secret 或 secret headers。

## 必须实现

1. JS API
   - 提供 `hostApi.callLlm(request)`。
   - 提供 canonical namespace `hostApi.llm.generate(request)`。
   - 不提供 AstrBot 风格别名。

2. 请求模型
   - 支持 `providerId`、`modelId`、`messages`、`systemPrompt`、`temperature`、`topP`、`maxTokens`、`tools` 只读输入。
   - message role 仅允许 `system`、`user`、`assistant`；tool message 第一阶段不开放给插件直接写入。
   - maxTokens、temperature、topP 必须校验范围。

3. 宿主执行
   - 新增 `PluginV2HostLlmPort` 或等价 port。
   - 内部复用 provider runtime，不复用插件 LLM hook pipeline。
   - 每次调用带 recursion guard 标记，明确 `bypassPluginLlmHooks = true`。

4. 返回模型
   - 返回 `text`、`finishReason`、`providerId`、`modelId`、`usage`、`toolCalls`。
   - 非流式返回。
   - provider 失败、模型不可用、限流、超时均返回 structured error。

5. 权限与治理
   - 使用 `call_model` permission。
   - 单插件并发、单次 timeout、maxTokens 上限和调用频率必须可配置或至少有硬编码保护。
   - 审计记录 provider/model、token usage、duration、failureCode。

## 必须补测试

- `PluginV2HostLlmApiTest`
  - 插件调用 fake provider 返回 text 与 usage。
  - 未授权时拒绝。
  - providerId/modelId 不存在时拒绝。
  - 参数范围非法时拒绝。
  - LLM hook 内调用 `hostApi.callLlm` 不触发同批插件 LLM hooks。
  - provider secret 不进入 JS 返回值或日志。

- provider port adapter test
  - fake provider runtime 可被 host LLM port 调用。
  - timeout 和 provider failure 映射为 structured error。

- architecture contract
  - plugin runtime 不直接读取 provider credential。
  - 不新增 static provider repository 使用。

- 插件可通过宿主调用非流式 LLM。
- 默认绕过插件 LLM hooks 的行为有测试锁定。
- provider secret 不泄露。
