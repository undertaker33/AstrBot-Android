## 目标

实现插件自注册定时任务回调，使插件可在 bootstrap 中声明 schedule handler，由 Cron runtime 持久化、调度并唤醒 Plugin V2 handler。

## 非目标

- 不新增平台 adapter。
- 不开放任意后台常驻 JS runtime。
- 不让插件直接操作 Cron DAO。
- 不复用 legacy V1 `on_schedule` 作为生产主线。
- 不实现 Agent 或 streaming。

## 必须实现

1. JS API
   - 提供 `hostApi.registerScheduledHandler({ key, cron, runAt, conversationId, handler })`。
   - handler key 在同一 plugin 内唯一。
   - 支持 cron 或 runAt 二选一。

2. 编译与持久化
   - bootstrap registry 编译 schedule descriptor。
   - Cron repository 保存 `pluginId`、`handlerKey`、`cron`/`runAt`、`conversationId`、`enabled`、`pluginVersion`。
   - 插件 enable 时 reconcile schedule。
   - 插件 disable / suspend 时暂停 schedule。
   - 插件 uninstall 时删除对应 schedule。
   - 插件 upgrade 后按 handler key reconcile。

3. 调度唤醒
   - Cron runtime 唤醒后进入 Plugin V2 dispatch。
   - event payload 包含 scheduledAt、jobId、conversationId、trigger source。
   - scheduled handler 可以调用 `T04` 的当前/绑定会话发送能力。

4. 权限
   - 注册使用 `schedule_manage` permission。
   - 发送消息仍需 `send_message` permission。
   - conversationId 必须来自当前事件绑定或用户授权的 target context。

5. 防重与失败治理
   - 同一 job 不并发重入。
   - handler 失败进入 plugin failure guard 或 Cron execution record。
   - schedule 执行日志可追踪 pluginId/handlerKey/jobId。

## 必须补测试

- `PluginV2ScheduledHandlerRegistryTest`
  - 注册 cron handler。
  - 同 plugin 重复 key 被拒绝或覆盖，语义固定。
  - 未授权时拒绝。

- `PluginV2ScheduledHandlerLifecycleTest`
  - enable 创建/恢复 schedule。
  - disable 暂停 schedule。
  - uninstall 删除 schedule。
  - upgrade 按 handler key reconcile。

- `PluginV2ScheduledDispatchTest`
  - Cron wakeup 进入 V2 handler。
  - handler 可向绑定会话发送消息。
  - handler failure 写 execution record 和 runtime log。

## 完成判定

- 插件 schedule 生命周期与插件 enable/disable/uninstall/upgrade 一致。
- Cron 唤醒进入 V2 handler。
- legacy `on_schedule` 不再作为新增生产主线。
