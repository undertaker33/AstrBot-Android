## 目标

实现插件当前会话内的流式输出能力，允许插件按 chunk 更新或发送消息，并为后续 LLM streaming 统一消息流抽象。

## 非目标

- 不实现 HTML 渲染。
- 不实现文本转图。
- 不要求 QQ 支持消息编辑；QQ 可降级为分段发送或最终一次发送。
- 不开放跨会话 streaming。
- 不实现 Agent streaming。

## 必须实现

1. JS API
   - 提供 `hostApi.message.openStream({ markdown })`。
   - stream handle 提供 `append(text)`、`replace(text)`、`close()`、`fail(message)`。
   - 只使用 canonical API，不提供 AstrBot 风格别名。

2. 宿主抽象
   - 定义 `PluginV2MessageStreamPort` 或等价 port。
   - 当前会话内创建 host-managed stream handle。
   - App Chat 优先支持 pending message append/update。
   - QQ adapter 不支持编辑时，明确降级为分段发送或最终一次发送。

3. 限制
   - 使用 `message_stream` permission。
   - 每个 stream 有 max duration、max chunks、max bytes。
   - handler 结束时未 close 的 stream 必须自动 close 或 fail。
   - cancellation 和 plugin unload 要关闭 stream。

4. 审计与错误
   - 记录 streamId、chunk count、bytes、duration、platform、failureCode。
   - append 超限返回 structured error。
   - 平台不可用返回 structured error 或 documented fallback。

## 必须补测试

- `PluginV2MessageStreamApiTest`
  - open/append/close 成功。
  - 未授权时拒绝。
  - chunk 超限时拒绝。
  - handler 结束未 close 时自动收口。
  - cancellation 关闭 stream。

- platform stream tests
  - App Chat fake stream 更新 pending message。
  - QQ fake adapter 使用固定降级策略。
  - 平台发送失败映射 structured error。
