## 目标

定义并落地插件富消息链模型，使插件可发送 text、image、file、mention、reply、card 等结构化消息，并在 App Chat 与 QQ 间有明确映射和 fallback。

## 非目标

- 不做 HTML 渲染。
- 不做文本转图。
- 不新增平台 adapter。
- 不允许插件绕过 media resolver 读取任意文件。
- 不要求所有 segment 在所有平台原生支持；必须允许 fallback。

## 必须实现

1. 消息模型
   - 定义 `PluginMessageSegment`。
   - 支持 `text`、`image`、`file`、`mention`、`reply`、`card`。
   - segment 字段必须可 JSON 序列化。
   - 不支持的 segment type 返回 structured error。

2. JS API
   - 扩展 `hostApi.message.send({ chain })`。
   - 简单 `text` 发送继续兼容 `T04`。
   - 不提供 AstrBot 风格别名。

3. Media resolver
   - `image` / `file` 只允许 `plugin://package`、`plugin://workspace`、宿主允许的 `content://` ref 或 HTTPS remote URL。
   - 相对路径必须解析在 plugin root / workspace 内。
   - 不允许任意绝对文件路径逃逸。

4. App Chat 映射
   - text 合并为正文。
   - image/file 映射到 `ConversationAttachment`。
   - mention/reply/card 不支持时生成 markdown/text fallback。

5. QQ 映射
   - text/mention/image/reply 尽量映射 OneBot segment。
   - file/card 不支持时使用 fallback text 或附件策略。
   - 不支持项必须返回 structured warning 或 recorded fallback，不静默丢弃。

6. 权限
   - 使用 `rich_message_send` permission。
   - 仍受当前会话约束。

## 必须补测试

- `PluginMessageSegmentTest`
  - JSON 解析与序列化。
  - 不支持 segment type 被拒绝。
  - media path escape 被拒绝。

- `PluginV2RichMessageSendApiTest`
  - text + image chain 在 App Chat 映射成功。
  - mention + reply 在 QQ 映射成功。
  - App Chat 不支持 mention/reply 时 fallback 可见。
  - 未授权时拒绝。
  - 跨会话发送仍拒绝。

- platform mapping contract
  - App Chat 和 QQ 对每种 segment 的支持矩阵被测试固定。
