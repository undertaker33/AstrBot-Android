## 目标

实现插件只读查询当前会话历史的 host API，为插件处理上下文、LLM 调用和 context compression 提供受控输入。

## 非目标

- 不开放跨会话历史读取。
- 不开放 conversation 写入、删除、编辑。
- 不暴露 Room entity、DAO、raw SQL 或内部数据库主键结构。
- 不读取 provider secret 或 bot private config。

## 必须实现

1. JS API
   - 提供 `hostApi.conversation.history({ limit, beforeMessageId, includeAttachments })`。
   - 只使用 canonical API，不提供 AstrBot 风格别名。

2. 查询约束
   - 只读当前 event 的 `conversationId`。
   - 默认 `limit = 20`，硬上限 `100`。
   - `beforeMessageId` 为空时读取最近消息。
   - 无当前会话上下文时拒绝。

3. 返回 DTO
   - 返回 `messageId`、`role` 或 `senderId`、`messageType`、`text`、`timestampEpochMillis`、`attachmentRefs`。
   - 附件只返回宿主可控 ref/uri 和 mime type。
   - 不返回 Room entity 或内部 DAO 字段。

4. 宿主 port
   - 通过 conversation/chat API 暴露只读 port。
   - plugin runtime 不直接依赖 conversation data implementation。

5. 权限与审计
   - 使用 `conversation_read` permission。
   - 审计记录 limit、conversationId、resultCount、failureCode。

## 必须补测试

- `PluginV2ConversationHistoryApiTest`
  - 当前会话返回最近 20 条。
  - limit 超过 100 被压到 100 或返回固定错误，语义必须测试固定。
  - beforeMessageId 生效。
  - 无当前会话上下文时拒绝。
  - 非当前会话读取被拒绝。
  - 未授权时拒绝。
  - 返回结果不含 Room entity 字段。

- conversation port adapter test
  - fake conversation store 映射为 plugin history DTO。
  - attachment ref 不逃逸宿主边界。

- architecture contract
  - plugin runtime 不直接依赖 conversation data。
  - 不新增 DB 直连。
