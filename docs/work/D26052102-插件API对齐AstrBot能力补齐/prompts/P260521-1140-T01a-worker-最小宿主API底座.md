## Required tests

Use TDD. Add tests first, run them and capture expected failures, then implement.

Create/update app JVM tests under `app/src/test/java/com/elymbot/android/runtime/plugin/`:

- `PluginV2HostApiPermissionPolicyTest`
  - manifest undeclared denies
  - user grant missing denies
  - trigger whitelist missing denies
  - runtime policy denies
  - all gates satisfied allows
- `PluginV2HostApiAuditLoggerTest`
  - success and failure include `pluginId`, `api`, `permissionId`, `conversationId`, `platformAdapterType`, `requestId`, `succeeded`, `failureCode`, `durationMs`
  - log metadata sanitizes `apiKey`, `baseUrl`, `headers`, `credential`, stack-trace-like values, and DAO/internal details
- `PluginV2HostApiAsyncBridgeTest`
  - successful suspend block returns success
  - timeout returns `timeout`
  - `IllegalArgumentException` returns `invalid_payload`
  - generic exception returns `execution_failed` and is logged
  - cancellation is preserved or converted to explicit `cancelled`, but must not be logged as raw stack

Do not require real QuickJS in T01a.

## Implementation constraints

- Permission evaluation order is fixed: manifest declaration, user grant, trigger whitelist, runtime policy.
- Well-known permission IDs must include:
  - `network_request`
  - `call_model`
  - `provider_read`
  - `send_message`
  - `conversation_read`
  - `schedule_manage`
  - `message_stream`
  - `rich_message_send`
  - `context_compress`
  - `agent_run`
- Structured error codes must include:
  - `permission_denied`
  - `timeout`
  - `invalid_payload`
  - `host_unavailable`
  - `execution_failed`
  - `cancelled`
- Audit logging must use `PluginRuntimeLogBus` and `PluginRuntimeLogCategory.HostAction` or another existing category; do not create a parallel log system.
- Keep the API Kotlin-first and reusable by later host API implementations.
