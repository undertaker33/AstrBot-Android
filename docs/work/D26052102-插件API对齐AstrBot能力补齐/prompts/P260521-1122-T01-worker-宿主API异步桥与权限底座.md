## Implementation guidance

- Keep the public JS/API naming canonical to ElymBot; do not expose AstrBot aliases.
- Prefer small model/data classes with explicit fields over stringly typed maps for core contracts.
- Use `PluginRuntimeLogBus` for audit/runtime logging; do not create a parallel log system.
- Permission evaluation order must be fixed: manifest declaration, user grant, trigger whitelist, runtime policy.
- Structured error codes must distinguish at least: `permission_denied`, `timeout`, `invalid_payload`, `host_unavailable`, `execution_failed`, `cancelled`.
- The async bridge should run host calls on an injected/supplied dispatcher, apply timeout, preserve cancellation, and never leak raw host exceptions to JS-facing results.
- Keep Hilt wiring minimal and only when required by production construction.
