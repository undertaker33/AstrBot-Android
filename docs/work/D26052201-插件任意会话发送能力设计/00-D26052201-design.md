# D26052201 插件任意会话发送能力设计

更新时间：2026-05-22 18:15 +08:00

## 场景

- Scene：`uth-design`
- Mode：`design-authoring`
- 目标：在 `D26052102` 已完成当前会话发送的基础上，设计插件向宿主授权的任意目标会话主动发送消息能力。
- 输出：任务包 Design。源码实现、Todo 文件拆分、Worker prompt、验收评审和 Git 写入均不在本轮执行。

## 已知约束

- 不暴露 AstrBot 风格别名；JS API 继续使用 ElymBot canonical `hostApi.*` 命名。
- 不放宽现有 `hostApi.message.send({ conversationId })` 当前会话 guard。现有字段继续表示“必须等于当前上下文会话”的安全校验。
- 不做 Web API 注册、平台适配器注册、DB 直连、文本转图或 HTML 渲染。
- 任意会话发送必须走宿主能力，插件不能直接操作 OneBot socket、Room DAO、adapter 实例或 provider secret。
- 网络能力仍走宿主代理；本设计不新增插件直连网络通道。

## AstrBot 参考语义

AstrBot 的主动发送核心不是当前事件对象，而是可持久化的 session 路由：

- `MessageSession` 表示 `platform_id:message_type:session_id`。
- 插件调用 `context.send_message(session, message_chain)`。
- 宿主按 `session.platform_name` 找到 platform adapter，再调用 `platform.send_by_session(session, message_chain)`。
- QQ/OneBot adapter 最终按群聊或私聊调用 `send_group_msg` / `send_private_msg`。

本设计只参考这个能力模型：插件持有一个宿主认可的目标路由句柄，发送时由宿主解析并交给对应平台。ElymBot 不直接公开 AstrBot session 字符串，也不要求插件自己拼平台路由。

## 当前 ElymBot 状态

`D26052102` 已完成：

- `hostApi.message.send`：当前会话发送。
- `hostApi.message.send({ chain })`：富消息链。
- `hostApi.message.openStream`：当前会话流式输出。
- `hostApi.registerScheduledHandler`：插件定时回调，但目标仍绑定当前事件上下文。
- `hostApi.conversation.history` / `hostApi.context.compress`：当前会话只读或压缩。

当前代码事实：

- `PluginV2MessageSendApi.resolveTargetConversationId(...)` 要求 `request.conversationId` 为空或等于当前 `context.conversationId`，否则返回 `conversation_scope_violation`。
- `PluginV2BootstrapHostApi.requireScheduledTargetContext(...)` 只允许 scheduled handler 的显式 target 匹配当前事件上下文；无当前上下文时不接受 raw explicit target。
- `ConversationSession` 已持有 `platformId`、`messageType`、`originSessionId`。
- `MessageSessionRef.unifiedOrigin` 已提供类似 `platformId:messageType:originSessionId` 的统一路由表达，但当前不是插件开放发送 API。
- `DefaultScheduledMessageDeliveryPort` 已能按 platform 把 scheduled message 投递到 App Chat 或 QQ。
- `QqScheduledMessageSender` / `QqOneBotOutboundGateway.sendScheduledMessage(...)` 已有主动 QQ 发送能力，但当前解析 `group:` / `friend:` 目标，尚不能直接作为插件任意目标授权模型。

## 设计决策

采用“宿主授权目标句柄”方案，而不是放开 `conversationId` 或公开 AstrBot session 字符串。

比较过的方案：

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 放宽 `hostApi.message.send({ conversationId })` | 拒绝 | 会破坏现有当前会话安全语义，插件只要知道 ID 就能跨会话发送 |
| 暴露 AstrBot 风格 session 字符串 | 拒绝 | 与用户确认的“不暴露 AstrBot 风格别名”冲突，也会让插件自己拼平台路由 |
| 新增宿主授权 `targetId` / route | 采用 | 保留现有 API 兼容性，目标由宿主列出、授权、解析和审计 |

## 公开 API 设计

### 当前会话发送保持不变

```javascript
await hostApi.message.send({
  text: "当前会话回复"
})
```

`conversationId` 仍只能省略或等于当前会话：

```javascript
await hostApi.message.send({
  conversationId: event.conversationId,
  text: "仍然是当前会话"
})
```

### 授权目标读取

新增目标读取 API：

```javascript
const targets = await hostApi.message.targets.list({
  platform: "qq",
  messageType: "group",
  limit: 50
})
```

返回结构建议：

```json
{
  "targetId": "target_7f2a...",
  "displayName": "群聊名称",
  "platformAdapterType": "qq_onebot",
  "messageType": "group",
  "conversationId": "qq-main-group-123456",
  "canSend": true
}
```

关键约束：

- 只返回宿主已经授权给该插件的 target。
- 不返回 provider secret、adapter socket、raw OneBot token 或数据库内部结构。
- `targetId` 由宿主签发或映射，插件不能通过拼接目标 ID 获得额外发送权。
- `conversationId` 只作显示、审计和本地记录关联，不作为跨会话发送授权依据。

### 目标会话发送

新增 targeted send 形态：

```javascript
await hostApi.message.send({
  targetId: "target_7f2a...",
  text: "主动发送到授权目标"
})
```

富消息链复用现有 `chain`：

```javascript
await hostApi.message.send({
  targetId: "target_7f2a...",
  chain: [
    { type: "text", text: "报告已生成" },
    { type: "image", uri: "plugin://workspace/report.png" }
  ]
})
```

语义：

- `targetId` 与 `conversationId` 同时出现时，`targetId` 优先，并要求 `conversationId` 与目标绑定的 local conversation 一致，否则拒绝。
- 无 `targetId` 时保持当前会话模式。
- 当前会话模式只要求 `send_message` 或 `rich_message_send`。
- 目标会话模式额外要求 `targeted_message_send`。

### 定时回调目标绑定

当前 `registerScheduledHandler` 只允许当前事件绑定。后续新增：

```javascript
hostApi.registerScheduledHandler({
  key: "daily-report",
  cron: "0 9 * * *",
  targetId: "target_7f2a...",
  handler: async (event) => {
    await hostApi.message.send({ text: "每日摘要" })
  }
})
```

设计语义：

- 注册时把 `targetId` 解析成稳定 `PluginMessageRoute` 并持久化到 schedule descriptor。
- handler 被唤醒时，`event.conversationId` / `event.platformAdapterType` 使用该授权 route 注入。
- handler 内继续调用普通 `hostApi.message.send({ text })` 即发送到绑定目标。
- 如果授权被撤销、target 不存在、QQ 未连接或 App Chat session 已删除，调度执行应返回 structured failure，而不是静默成功。

## 内部模型

新增宿主内部模型，避免插件直接持有平台路由：

```kotlin
data class PluginMessageTarget(
    val targetId: String,
    val pluginId: String,
    val conversationId: String,
    val platformAdapterType: String,
    val messageType: MessageType,
    val originSessionId: String,
    val botId: String,
    val displayName: String,
    val grants: Set<String>,
)
```

发送时解析为：

```kotlin
data class PluginMessageRoute(
    val conversationId: String,
    val platformAdapterType: String,
    val messageType: MessageType,
    val originSessionId: String,
    val botId: String,
)
```

route 只在宿主内流转。QuickJS 侧只能看到 `targetId` 和脱敏 display 字段。

## Port 与模块边界

建议新增或扩展以下 port：

- `PluginV2MessageTargetReadPort`
  - `listAuthorizedTargets(pluginId, filters)`
  - `resolveAuthorizedTarget(pluginId, targetId)`
  - `resolveCurrentTarget(context)`
- `PluginV2TargetAuthorizationPort`
  - 判断插件是否具备目标读/发权限。
  - 后续可接 UI 授权、manifest policy 或用户配置。
- `PluginV2MessageSendPort`
  - 扩展 request，支持 `route: PluginMessageRoute?`。
  - 无 route 时维持当前 `conversationId + platformAdapterType` 行为。
- `QqOutboundMessageSender`
  - 可先由 `QqScheduledMessageSender` 承担实现，但语义上应抽成“QQ 主动发送”而不是只属于 cron。

模块边界：

- `feature/plugin/runtime` 只做 host API、权限、审计、target resolver 调用和 structured error。
- `feature/conversation/api/data` 继续作为 App Chat session 与本地记录真源。
- `feature/qq/api/runtime` 负责 QQ 主动发送 port 和 OneBot action。
- `app-integration` 负责 Hilt wiring，把 conversation、QQ、plugin target resolver 接起来。
- 不允许 `feature/plugin/runtime` 直接 import Room DAO、QQ runtime graph factory 或 OneBot transport。

## 目标解析策略

App Chat：

- `platformAdapterType = app` 或 `app_chat`。
- `conversationId` 是本地 conversation session id。
- 发送结果为 `ConversationRepositoryPort.appendMessage(...)` 返回的 message id。

QQ：

- `platformAdapterType = qq_onebot` 或现有 QQ 平台 wire value。
- `originSessionId` 必须规范化为：
  - `friend:<userId>`
  - `group:<groupId>`
- 如果现有 isolated group session 是 `group:<groupId>:user:<userId>`，主动发送必须退化为群目标 `group:<groupId>`，不能把 `groupId:user:userId` 直接传给 OneBot `group_id`。
- `botId` 为空时使用当前默认/绑定 QQ bot；如果目标来自具体 bot，会携带 `botId` 并使用对应 config decoration。

## 权限与审计

新增权限建议：

| Permission | 用途 |
| --- | --- |
| `message_target_read` | 读取宿主已授权给插件的目标列表 |
| `targeted_message_send` | 向非当前上下文目标发送消息 |

复用现有权限：

- `send_message`：普通文本/附件发送。
- `rich_message_send`：富消息链发送。
- `schedule_manage`：注册目标绑定的 scheduled handler。

目标发送的权限组合：

- 文本目标发送：`send_message` + `targeted_message_send`。
- 富消息目标发送：`rich_message_send` + `targeted_message_send`。
- 读取可发目标：`message_target_read`。
- 注册目标定时回调：`schedule_manage` + `targeted_message_send`。

审计字段需要扩展：

- `targetId`
- `targetConversationId`
- `targetPlatformAdapterType`
- `targetMessageType`
- `targetOriginHash`
- `targetAuthorizationSource`
- `botId`

`targetOriginHash` 用于审计定位，不直接把 QQ 号/群号长期写入普通 runtime log。

## 错误语义

新增 structured error：

| Code | 场景 |
| --- | --- |
| `message_target_permission_denied` | 未声明或未授权目标能力 |
| `message_target_not_found` | targetId 不存在或不属于当前插件 |
| `message_target_revoked` | 目标曾存在但授权已撤销 |
| `message_target_unavailable` | 平台未登录、QQ reverse WS 未连接或 App Chat session 不可用 |
| `message_target_scope_violation` | `targetId` 与显式 `conversationId` 不匹配 |
| `message_target_platform_unsupported` | 目标平台暂无主动发送实现 |

现有 `conversation_scope_violation` 保留给当前会话模式。

## 验收标准

功能验收：

- 未声明 `targeted_message_send` 的插件不能跨会话发送。
- 插件不能通过 raw `conversationId` 绕过当前会话 guard。
- 插件只能读取和发送宿主授权给自己的 target。
- App Chat 目标发送会写入对应 conversation。
- QQ 私聊目标发送会调用 `send_private_msg`。
- QQ 群目标发送会调用 `send_group_msg`，isolated group session 不会把 `group:<id>:user:<id>` 误传为 group id。
- 目标授权撤销后，已有 `targetId` 发送失败并返回 structured error。
- scheduled handler 绑定 `targetId` 后，唤醒上下文能注入正确 conversation/platform，并允许 handler 内普通发送。

## 风险

- 目标发送具备主动触达能力，必须默认最小授权，避免插件群发或误发。
- QQ route 不能继续依赖宽松字符串解析；必须显式区分 local conversation id、origin session 和 OneBot target id。
- 目标列表可能泄露用户联系人/群信息；必须按插件授权过滤，并控制 display 字段。
- scheduled handler 持久化 target 后，授权撤销、会话删除、bot 解绑都要有明确失败语义。
- App Chat 与 QQ 都会写本地 conversation 记录，重复写入和 receipt id 合并需要测试覆盖。
