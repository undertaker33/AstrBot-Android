## 目标

让完整备份与 Persona 单模块备份同时携带三标签、封面主图和两套裁切参数；恢复时兼容缺少所有新增字段的老包，并对单图损坏进行非阻断降级。

## 全局约束

- 包内只保存相对 archive path、长度和 SHA-256，不保存设备绝对 `filesDir` 路径。
- 老 JSON-only 包、旧 ZIP 包和无 cover/tags 字段的 Persona 记录必须继续可读。
- 单个封面缺失、哈希不符或无法解码时恢复 Persona 数据、回退默认图并产生 warning，不中止整包。
- 恢复必须先进入应用私有 staging；Room 与文件发布失败均可补偿，不提前删除旧封面。
- 冲突行为严格跟随 `MERGE_SKIP_DUPLICATES`、覆盖重复和 `REPLACE_ALL` 现有语义。

## 非目标

- 不修改备份页面视觉。
- 不改变非 Persona 模块的导入冲突语义。
- 不放宽 Zip Slip、文件大小、hash 或解码安全校验。

## 目标包结构

```text
manifest.json
assets/persona-covers/<personaId>/<assetUuid>.<ext>
```

Persona manifest record 包含 `tags`、可选 cover metadata、两套 crop spec、archive path、length 和 sha256。旧字段 `tag` 保持只读兼容入口，不再作为新包写出真源。

## 实施步骤

1. 先补失败测试矩阵：完整备份 round-trip、Persona 模块 round-trip、旧 JSON-only、旧 ZIP、无 tags、无 cover、缺文件、hash 错误、不可解码图片和三种冲突模式。
2. 扩展 manifest adapters：新包写 `tags` 与 cover block；读取优先 `tags`，缺失时把旧 `tag` 规范化为最多三项。
3. 扩展 `resolveZipEntries(...)`，完整备份和 Persona 模块备份都仅打包当前有效 cover asset。
4. 读取 ZIP 时把封面解压到受控 staging，验证路径、长度、SHA-256 和可解码性；单图失败写 warning 并清除该 Persona 的 incoming cover metadata。
5. 扩展 backup data port，使 restore plan 同时携带 Persona records 与已验证 cover staging assets。
6. 按冲突模式决定每个同 ID Persona 的结构化数据与封面归属；`MERGE_SKIP_DUPLICATES` 不替换本地封面，覆盖重复采用备份封面，`REPLACE_ALL` 清理恢复后未引用旧资产。
7. Room 提交成功后发布 staging 文件；发布或后续步骤失败执行补偿 / rollback，并保留恢复前可用数据。
8. 在恢复结果中汇总 cover warnings，不把 warning 标记成整包失败。
