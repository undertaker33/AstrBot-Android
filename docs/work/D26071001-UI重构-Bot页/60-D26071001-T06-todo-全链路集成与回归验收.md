## 验收矩阵

1. **Room**：23 → 24 migration、标签顺序、封面 metadata、级联删除、schema 同步。
2. **文件生命周期**：来源只读、导入后离线可用、替换补偿、Persona 删除、orphan cleanup、路径逃逸。
3. **备份**：完整包、Persona 包、旧包、单图损坏、三种冲突模式、rollback。
4. **目录 UI**：双模式持久化、模式一箭头、模式二固定错位、顶栏 overlay 互斥、三标签搜索筛选。
5. **详情 UI**：五字段、固定提示词、两态面板、动态居中、纵向 / 方形两步 crop。
6. **回归**：机器人页、模型页、外层滑动、全局底栏、Persona 引用保护、runtime context、备份其他模块。
7. **命名**：生产 strings、contentDescription 和测试中用户可见语义均为“人格”；不存在新增 Role 页面或路由。

## 实施步骤

1. 建立 Design requirement → test / command 的验收追踪表，缺少证据的条目先补测试。
2. 运行 T01–T05 各自窄测试，确认不是依赖增量构建缓存的偶然通过。
3. 运行 Room migration instrumentation / schema contract，核对 app 与 core 两份 24 schema 字节或结构一致。
4. 运行 Persona、backup、navigation、runtime context 和 architecture tests，修复组合回归。
5. 对定稿图逐项执行 Compose UI / screenshot contract 或人工设备检查：浅色、深色、小屏、长名称、三标签、超长提示词、单 Persona、空 Persona。
6. 执行 `architectureCheck`、相关 module checks 和 `clean assembleDebug`；扫描日志中的 warning / deprecated / exception / failed。
7. 写 T06 Feedback，列出所有验证命令、0 warning / 0 exception 证据、无法自动验证的设备项和最终 `Needs uth-docs scoped-sync`。
8. 更新 `docs/current-state.md` 为“Todos 已实现，待 uth-review”，不在本 Todo 宣称 Design-level 验收完成。
