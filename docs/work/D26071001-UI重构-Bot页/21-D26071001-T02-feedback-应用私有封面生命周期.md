## Rework 1：metadata 失败后的真实重试

- Reviewer finding：旧 `commit()` 先把 draft `renameTo(published)`；metadata 更新失败虽删除 published，却让 `pending` 继续指向已不存在的 draft，导致 UI 保留的失败态无法真实重试。
- RED：新增真实 `PersonaCoverAssetManager` 文件 I/O 用例，令 metadata store 首次失败、第二次成功；旧实现于首次失败后的 `draftFile.isFile` 断言失败（2 tests completed, 1 failed）。另覆盖失败后 `discard()` 清理 draft。
- GREEN：commit 改为复制 draft 到 published，metadata 成功后才移除 pending、删除 draft、删除旧封面；metadata 失败只删除临时 published，旧 metadata/旧文件与完整可读 draft/pending 均保留。
- 重试证据：首次失败后磁盘仅保留旧封面和内容为 `normalized` 的 draft；第二次 commit 成功后 published 可读、draft 与旧封面均清理，metadata 指向新 asset。失败后 discard 路径仅删除 draft，旧状态不变。
