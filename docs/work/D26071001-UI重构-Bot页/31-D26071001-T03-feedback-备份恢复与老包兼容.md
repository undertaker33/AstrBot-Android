## 实现摘要

- 新 Persona manifest 写出 `tags`、可选 cover block、纵向/方形 crop、相对 `archivePath`、`length` 与 `contentSha256`，不再写旧 `tag` 真源或设备绝对路径。
- 完整备份与 Persona 单模块备份共用 manifest/ZIP 入口，均会收集有效 `assets/persona-covers/**` 文件。
- 读取优先 `tags`，缺失时兼容旧单 `tag`；无 tags、无 cover、JSON-only 与旧 ZIP 继续沿用既有解析入口。
- 实际 restore 才物化 Persona cover；预览不发布文件。恢复文件先来自受控 ZIP extraction staging，并校验路径、长度、SHA-256 与图片解码。
- 缺文件、hash 不符或无法解码会移除 incoming cover metadata、记录 warning 并恢复 Persona 默认封面，不中止整包。
- 文件发布使用新的应用内 `import-*` 相对引用，避免提前覆盖旧封面。成功后清理 resolved 结果未引用的 incoming/旧封面；恢复失败清理本次 incoming 文件并由既有 stage rollback 恢复结构化数据。
- ZIP 读写增加 archive path 与 canonical boundary 校验，未放宽 Zip Slip 边界。

## 冲突模式与补偿矩阵

- `persona_merge_skip_duplicates_keeps_local_cover`：重复 Persona 保留本地封面，丢弃 incoming 文件。
- `persona_merge_overwrite_duplicates_uses_incoming_cover`：覆盖重复采用 incoming 封面，成功后清理旧封面。
- `persona_replace_all_uses_only_incoming_covers`：仅保留 incoming Persona/封面，清理恢复后未引用旧资产。
- `persona_cover_cleanup_plan_covers_skip_overwrite_replace_and_rollback`：集中验证 skip、overwrite、replace 与 restore failure 的清理集合。
- `importBackup_rolls_back_previously_restored_modules_when_later_stage_fails`：既有兼容测试继续验证后续 stage 失败时 Persona 等已应用结构化数据逆序 rollback。
