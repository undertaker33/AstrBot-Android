## 目标

建立 Persona 封面应用私有资产 port 与实现，完成 URI 只读导入、方向纠正、最长边 2048px 规范化、staging、补偿式替换、删除和孤儿清理，同时从类型与路径校验上保证用户原文件永不被删除。

## 全局约束

- 受控根目录固定为 `filesDir/assets/persona-covers/`。
- Room 仅保存相对 `assetRef`；任何解析后的绝对路径必须重新验证仍位于受控根目录。
- 来源 URI 只允许 `openInputStream` 读取；生产代码不得调用 `ContentResolver.delete`、`DocumentFile.delete` 或对来源打开写流。
- 新文件成功提交 Room 后才能删除旧应用内文件；失败必须保留旧引用和旧文件。
- 不引入新的图片加载 / 裁切依赖，除非用户另行明确授权。

## 非目标

- 不实现备份打包与恢复；T03 负责。

## 目标接口

在 persona API 暴露 Android-free 语义合同：

```text
PersonaCoverAssetPort
├─ stageImport(personaId, sourceUriString) -> PersonaCoverDraft
├─ commit(draftId, portraitCrop, squareCrop) -> PersonaCoverMetadata
├─ discard(draftId)
├─ deleteForPersona(personaId)
├─ resolveReadableFile(assetRef)
└─ cleanupOrphans(gracePeriod)
```

实现可在 data 层解析 `sourceUriString` 为 `Uri`，但 domain model 不持有 `Uri`、`File` 或 `Bitmap`。`PersonaCoverDraft` 只暴露 opaque draft id、应用内临时预览引用和规范化像素尺寸。

## 实施步骤

1. 先写失败测试覆盖路径逃逸、云端 / 来源读取失败、EXIF 方向、2048px 上限、Room 失败补偿、旧文件删除顺序和 orphan 宽限期。
2. 建立 `PersonaCoverStoragePaths`，集中生成 staging、正式目录、UUID 文件名并执行 canonical path containment 检查。
3. 实现只读导入：流式复制来源到 staging，检查字节上限和可解码性，应用方向后生成最长边不超过 2048px 的高质量主图。
4. 实现 draft lifecycle：未确认裁切时只存在 staging；取消、异常或进程恢复清理过期 draft。
5. 实现 commit 补偿：发布新正式文件 → repository 更新 cover metadata → 成功后删除旧私有文件；repository 失败则删除新文件并保留旧状态。
6. 实现 Persona 删除后的私有目录清理；删除失败写日志并留给 orphan cleanup，不回滚已成功的业务删除。
7. 实现 orphan cleanup：只扫描受控根目录，对照 repository 中有效 `assetRef`，跳过宽限期内文件，拒绝符号链接 / canonical path 逃逸。
8. 增加 Hilt binding，生产路径不得使用 static install/configure callback。

## 完成证据

- 测试证明来源 URI 只读，且不存在删除用户原文件的生产调用。
- 导入成功后即使来源删除或不可达，应用内副本仍可解码。
- replacement 成功只删除旧私有副本；失败保留旧封面。
- cleanup 只触达受控根目录并遵守宽限期。
