## 目标接口

`PersonaProfile` 使用：

```kotlin
data class PersonaProfile(
    val id: String,
    val name: String,
    val tags: List<String> = emptyList(),
    val systemPrompt: String,
    val enabledTools: Set<String>,
    val defaultProviderId: String = "",
    val maxContextMessages: Int = 12,
    val enabled: Boolean = true,
    val cover: PersonaCoverMetadata? = null,
)
```

`PersonaCoverMetadata` 至少包含 `assetRef`、`contentSha256`、像素宽高、`portraitCrop`、`squareCrop` 和 `updatedAt`。裁切参数使用归一化中心点与正数缩放，并在构造 / mapper 边界执行有限值和范围校验。

Room 新增：

- `PersonaTagEntity(personaId, tag, sortIndex)`，复合主键 `(personaId, tag)`，索引 `(personaId, sortIndex)`，外键级联删除。
- `PersonaCoverAssetEntity`，以 `personaId` 为主键，外键级联删除。
- `PersonaAggregate` 与 `PersonaWriteModel` 纳入 tags / cover；`replaceAll` 同一事务内替换全部子表。

## 实施步骤

1. 先为标签规范化、裁切参数校验和 mapper round-trip 编写失败测试。
2. 在 persona API 中定义 `PersonaCropSpec`、`PersonaCoverMetadata` 与 `PersonaProfile.tags`，提供统一 `normalizePersonaTags(...)`，规则为去空白、过滤空项、稳定去重、最多三项。
3. 新增 `PersonaTagEntity`、`PersonaCoverAssetEntity`，扩展 aggregate、write model 和 DAO 的查询 / replaceAll 事务。
4. 新增 `migration23To24`：创建新表，把旧 `persona_profiles.tag` 规范化迁入 `persona_tags`，重建 `persona_profiles` 去除 `tag` 列，并保持其他字段、排序和更新时间不变。
5. 更新 `ElymBotDatabase` 版本、entities 和 migration 数组；导出两处 24 schema，并证明 schema 内容一致。
6. 更新 `PersonaMappers.kt`、legacy import 和 repository store，使所有读写只消费 `tags` 与 cover metadata。
7. 修复直接构造 `PersonaProfile(tag = ...)` 的生产 / 测试调用，旧 JSON / legacy 数据仍通过兼容解析转换为 `tags`。
8. 运行窄测试、Room contract 和 persona module test；失败时只在本 Todo 范围内收口。
