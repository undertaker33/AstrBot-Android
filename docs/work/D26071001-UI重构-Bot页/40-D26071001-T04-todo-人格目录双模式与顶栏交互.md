## 目标

把现有人格目录改造成可持久切换的沉浸单卡与双列错位两种模式，并实现互斥的顶栏搜索、固定筛选弹窗和更多菜单，同时保持“人格”命名、原页面位置、外层滑动导航和全局底栏不变。

## 全局约束

- 用户可见文案只使用“人格”“编辑人格”“新增人格”；“角色 / Role”保留给后续多 Agent。
- 机器人页、模型页、`MainSwipeRailState` 页面顺序与现有横向导航不改。
- 定稿图中的底栏不是实现真源，必须复用现有 Android 全局底栏。
- 正式 UI 使用 Material Icon / Vector Drawable，不使用文本字符或 Emoji 冒充图标。
- 模式偏好持久化；主题切换不改变模式。

## 非目标

- 不实现人格详情表单和两步裁切交互；T05 负责。
- 不修改 Room schema、图片文件生命周期或备份。
- 不创建 Role 页面或聚合 Bot / Config / QQ 状态。

## 目标状态

```text
PersonaPageUiState
├─ personas
├─ browseMode: IMMERSIVE_CARD / STAGGERED_GRID
├─ visiblePersonaId / pageIndex
├─ topOverlay: NONE / SEARCH / FILTER / MORE
├─ searchQuery
├─ appliedTagFilters
├─ pendingTagFilters
└─ loading / empty / failure
```

新增 `PersonaPresentationPreferencesPort` 持久化 browse mode，production implementation 走 Hilt。过滤语义为：名称或任一 tag 命中搜索；筛选选择多个标签时采用 OR 语义，即人格至少包含一个已选标签便命中。该规则由单一纯函数与测试固定，不在 Composable 内分叉实现。

## 实施步骤

1. 先写 reducer / state 测试，覆盖模式恢复、overlay 互斥、搜索收起、filter pending/apply/reset/dismiss 和 tag 过滤。
2. 将 `PersonaScreen.kt` 拆为 Route / state holder、共享顶栏、沉浸内容和错位列表等职责清晰的文件，避免继续扩大单文件。
3. 实现模式一：单卡占满内容区，卡内正式左右箭头切换 Persona，首尾 / 单项状态正确，封面使用纵向 crop metadata。
4. 实现模式二：双列等宽等高固定矩形卡，右列固定下沉 `64–72dp`，图片 / 名称 / 标签均不改变卡片尺寸，封面使用方形 crop metadata。
5. 实现共享顶栏搜索：约 75% 宽、自动聚焦和软键盘、外部点击 / 返回收起、清空保持展开。
6. 实现固定尺寸标签筛选弹窗：标签区独立滚动，重置只改 pending，确定才提交，dismiss 丢弃 pending。
7. 实现更多菜单：固定“新增人格”和当前模式的反向切换项；无新增 FAB、无内容区搜索 / chip 行。
8. 接入详情导航事件占位合同，编辑按钮只发 `EditPersona(personaId)`，不在目录页直接更换封面。
9. 复用当前 App 底栏与外层页面导航，并补 source contract 防止误改机器人 / 模型 / 人格顺序。
