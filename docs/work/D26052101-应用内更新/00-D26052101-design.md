# D26052101 应用内更新设计

更新时间：2026-05-21 01:05 +08:00

## 场景

- Scene：`uth-design`
- Mode：`design-authoring`
- 目标：新增应用内更新能力，在应用启动时检测 GitHub Release 最新 APK，发现新版本时弹出强制决策弹窗，并复用现有下载能力展示进度、下载 APK、拉起系统安装器和清理安装包。
- 本设计只定义实现边界与验收标准；源码变更应交给后续 `uth-dev`。

## 需求边界

本任务必须满足：

- 每次打开应用检测一次；应用使用期间不做周期检查，也不在后台主动弹窗。
- 更新源只允许项目 GitHub Release 页最新 release 的 APK asset，不使用 tag 列表、HTML 抓取、source zip/tarball 或其他镜像。
- 当前 build 为 debug 时只选择 debug APK；当前 build 为 release 时只选择 release APK。
- 有更新时显示应用内弹窗；点击外部、返回键或空白区域不得关闭初始决策弹窗。
- 初始决策弹窗必须是三选一：`更新`、`暂不更新`、`忽略此版本`。
- `暂不更新` 对当前 release 延后 1 天再弹；若最新 release tag 变化，应允许新版本重新提示。
- `忽略此版本` 只忽略当前 release tag；下一个 release tag 发布后应重新提示。
- 下载过程需要展示进度条；有总大小时显示确定进度，无总大小时显示不确定进度。
- 下载完成后在弹窗内提示安装；点击后以系统默认打开 APK 的方式交给系统安装器。
- 安装完成后自动清理已下载 APK。

当前工作树已有上一轮中断前落盘的 `app/src/main/java/com/elymbot/android/update/**`、Manifest、strings、download/network 枚举和测试半成品。它们是待核对的实现草稿，不等于本设计已完成交付。

## 当前事实

仓库上下文：

- `:app` 是 Manifest、Application、Activity、theme/resources、app shell 与 thin platform adapter owner。
- `:download:api` / `:download:impl` 已提供 `DownloadManagerPort`、`DownloadRequest`、`DownloadTaskRecord`、下载前台服务和进度数据。
- 插件远程包下载已经通过 `DownloadManagerPort` 走生产下载主线，可作为进度弹窗体验参考。
- `core/network` 已有 `RuntimeNetworkTransport`、`RuntimeNetworkRequest`、`RuntimeNetworkCapability` 与 timeout profile。
- 生产依赖注入必须走 Hilt / constructor injection，不得新增 service locator、static registry 或手写 app container。

外部文档事实：

- GitHub REST `GET /repos/{owner}/{repo}/releases/latest` 返回最新的非 draft、非 prerelease release；实现需要读取 `tag_name`、`name`、`html_url`、`draft`、`prerelease` 和 `assets[]`。
- Release asset 需要使用 `assets[].name` 判断 debug/release APK，使用 `assets[].browser_download_url` 作为下载 URL，读取 `size`、`content_type`、`state`、`digest` 作为辅助校验和显示。
- Android 对外提供 app-private APK 时需要 `FileProvider` content URI 和 `FLAG_GRANT_READ_URI_PERMISSION`。
- 目标 API 大于 25 的安装请求需要声明 `android.permission.REQUEST_INSTALL_PACKAGES`。

当前线上 release 事实（2026-05-21 通过 GitHub CLI 查询）：

- 最新 release：`v1.0.0`
- 状态：非 draft、非 prerelease
- assets：
  - `app-debug.apk`
  - `app-release.apk`
- 当前 `app/build.gradle.kts` 版本事实在上下文中为 `versionName = "1.0.0"`、`versionCode = 76`，因此当前实现完成后，在 `v1.0.0` 仍为最新时不应弹更新提示。

## 设计决策

### 1. 模块归属

应用更新属于 app shell 能力，落在 `:app` 的 `com.elymbot.android.update` 包内；它可以消费由 `app-integration` 暴露的 `DownloadManagerPort` 与 `RuntimeNetworkTransport`，但不引入新的 feature data/runtime owner。

Hilt 边界：

- `AppUpdateViewModel` 使用 `@HiltViewModel`。
- `AppUpdateRepository` 使用 constructor injection。
- 本地抑制/清理状态存储应使用可注入的 app-local store；如果保留简单 SharedPreferences wrapper，也应由 Hilt 构造或作为 repository 私有实现细节，不得成为静态全局入口。

### 2. 检测流程

启动入口：

1. `MainActivity` 在 app content 初始化后触发一次 `AppUpdateViewModel.checkForUpdateOnce()`。
2. ViewModel 用进程内/Activity 内 guard 防止一次打开期间重复检查。
3. 检查失败只写 `RuntimeLogger`，不弹失败提示，避免把网络瞬时失败变成用户阻断。

Release 判断：

1. 请求 `https://api.github.com/repos/undertaker33/ElymBot/releases/latest`。
2. 非 2xx、JSON 解析失败、空 tag、draft、prerelease、无匹配 APK asset 均视为无可提示更新。
3. `tag_name` 与 `BuildConfig.VERSION_NAME` 做规范化版本比较；只有 remote 版本严格大于当前版本才提示。

### 3. Asset 选择

选择规则必须稳定且可测试：

- 只考虑 `state == uploaded`、文件名以 `.apk` 结尾、`browser_download_url` 为 HTTPS 的 asset。
- `BuildConfig.DEBUG == true` 时，只选择文件名包含 `debug` 的 APK。
- `BuildConfig.DEBUG == false` 时，只选择文件名包含 `release` 且不包含 `debug` 的 APK。
- 如果目标 track 缺失，跳过提示并写日志；不要用 source zip、tarball 或错误 track 的 APK 兜底。
- 当前 release 命名约定为 `app-debug.apk` / `app-release.apk`，后续 release 也应保持该约定。

### 4. 用户决策状态

本地状态按 release tag 维度保存：

- `ignoredTagName`：命中当前 latest tag 时不提示；latest tag 变化后失效。
- `snoozedTagName + remindAfterEpochMillis`：仅对同一个 tag 生效；到期后允许再次提示；latest tag 变化后立即允许提示新 release。
- `pendingCleanupTag + pendingCleanupFile`：下载完成并准备安装后记录，用于安装完成后清理。

这避免“暂不更新”把一天内新发布的 release 也压住。

### 5. 弹窗状态机

弹窗由 `AppUpdateUiState` 驱动，所有 dialog 的 `onDismissRequest` 都为空实现，禁止点外部关闭。

状态：

- `Available`：初始三选一，按钮为 `更新`、`暂不更新`、`忽略此版本`。
- `Downloading`：显示 APK 名称、进度条、已下载/总大小、速度；无取消按钮，避免下载中留下未定义状态。
- `ReadyToInstall`：显示版本与文件名，只有 `安装` 按钮。
- `Failed`：必须仍给用户明确决策出口，建议提供 `重试`、`暂不更新`、`忽略此版本`，而不是只有 `关闭`；否则不满足初始弹窗强制三选一的产品语义。

插件 deep link 确认弹窗优先级高于更新弹窗；当插件安装确认存在时，更新弹窗应暂缓显示，避免两个 modal 叠加。

### 6. 下载与安装

下载：

- 使用 `DownloadManagerPort.enqueue()` 与 `awaitCompletion()`，新增 `DownloadOwnerType.APP_UPDATE`。
- task key 使用 `app-update:<tag>:<track>`，目标路径为 `filesDir/app-updates/<tag>/<assetName>`。
- 复用下载记录的 `downloadedBytes`、`totalBytes`、`bytesPerSecond` 显示进度；如果 release asset 有 `size`，可作为总大小兜底。
- 若已有目标文件大小与 asset size 不一致，应删除重下；`.part` 文件大于 expected size 时也应删除。

安装：

- 使用 `FileProvider` 暴露 `filesDir/app-updates/` 下 APK。
- Intent 使用 APK MIME `application/vnd.android.package-archive`，加 `FLAG_GRANT_READ_URI_PERMISSION`。
- 首选 `ACTION_VIEW` 以满足“系统默认打开 APK”；如验证发现特定 Android 版本/OEM 不可靠，再在 `uth-dev` 中评估 `ACTION_INSTALL_PACKAGE` fallback。
- Manifest 声明 `REQUEST_INSTALL_PACKAGES`、`FileProvider` 和 `MY_PACKAGE_REPLACED` receiver。

清理：

- 点击安装前记录待清理 tag/path。
- `ACTION_MY_PACKAGE_REPLACED` receiver 触发后，如果当前 `BuildConfig.VERSION_NAME` 已不小于待清理 tag，则删除 APK 与空 release 目录。
- 应在下一次启动检测前也执行同样清理，覆盖 receiver 未触发或进程状态异常的情况。

## 方案取舍

采用 GitHub REST latest release，而不是抓取 Release HTML：

- REST 响应结构稳定，能直接拿到 tag、draft/prerelease、asset 名称、大小、content type 和下载 URL。
- HTML 抓取对页面结构变化敏感，且难以可靠区分 debug/release APK。

复用 `DownloadManagerPort`，不新增单独下载器：

- 现有下载主线已经有 Room task、可恢复下载、前台服务和进度记录。
- 新增 owner type 的影响面小，测试合同可以覆盖。

应用更新留在 `:app`：

- 这是应用自身安装包更新能力，属于 Manifest、Activity、系统安装器和 app-private 文件暴露边界。
- 不应放入 plugin/feature runtime，也不应让 feature 反向依赖 app shell。

## 风险与待开发核对项

- 当前草稿中 release track 选择如存在“release fallback 到任意非 debug APK”的逻辑，`uth-dev` 应收紧为必须匹配 release token。
- 当前草稿中 snooze 如只存时间戳、不存 tag，`uth-dev` 应改为 tag-scoped snooze。
- `Failed` 弹窗如果只有 `关闭`，需要调整为不破坏强制决策语义。
- `RuntimeNetworkCapability.APP_UPDATE`、`RuntimeTimeoutProfile.APP_UPDATE` 和 `DownloadOwnerType.APP_UPDATE` 新增后，需要补对应模型/合同测试。
- Manifest 新增 `FileProvider`、receiver 和安装权限后，需要补 Manifest 合同，避免和现有 AndroidX Startup provider、bridge service、cleartext 约束冲突。
- `AppUpdateLocalStore` 的注入方式需要核对 Strict Hilt 合同，不能形成新的手写生产依赖图。
- 下载完成后的 APK 完整性当前只依赖传输完成与大小；如果 GitHub asset `digest` 可稳定提供，可在后续任务中评估 sha256 校验，但本任务不把 digest 校验设为阻塞需求。

## 验收标准

功能验收：

- 当前版本等于 latest tag 时不弹窗。
- latest tag 高于当前版本且存在当前 track APK 时，启动一次后弹出更新提示。
- 初始提示不能点外部关闭，必须在 `更新`、`暂不更新`、`忽略此版本` 中选择。
- `暂不更新` 对同一 tag 24 小时内不再弹，24 小时后再弹；新 tag 不受旧 tag snooze 影响。
- `忽略此版本` 对同一 tag 不再弹；新 tag 发布后重新弹。
- debug build 只下载 debug APK；release build 只下载 release APK。
- 下载时显示进度；下载完成后提示安装；点击安装能拉起系统安装器。
- 安装成功后 APK 文件被清理。

验证入口：

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests "com.elymbot.android.update.*" --console=plain --no-daemon --stacktrace
.\gradlew.bat :app:testDebugUnitTest --tests "*RuntimeNetworkModelsTest*" --tests "*MainActivityPluginDeepLinkTest*" --tests "*AndroidManifestRuntimeContractTest*" --console=plain --no-daemon --stacktrace
.\gradlew.bat architectureCheck --console=plain --no-daemon --stacktrace
.\gradlew.bat clean assembleDebug --console=plain --no-daemon --stacktrace
```

稳定收尾仍需遵守仓库门禁：`clean assembleDebug` warning / deprecated / exception 扫描计数为 0。
