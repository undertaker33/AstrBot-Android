## 原始请求

插件成功调用 `hostApi.conversation.history({ limit: 100 })`，但宿主返回空历史。根因是 QQ 普通群消息没有完整进入插件可读的群历史数据源；群分析不能依赖 bot 对话上下文，宿主需要在 QQ 群消息入口维护独立的公共群消息历史。

## 范围与非目标

本轮只处理 QQ 群消息公共历史沉淀与插件 Host API 读取路径：

- QQ 收到群消息后写入公共群历史 session。
- `hostApi.conversation.history` 在群场景优先读取公共群历史。
- 群聊 session 隔离仍只影响 bot LLM 对话上下文，不影响群分析历史。
- 不新增 DB schema，不做 DB 直连。
- 不做 Web API 注册、平台适配器注册、文本转图、HTML 渲染。
- 不新增网络能力，网络能力仍走宿主。
- 不执行 Git 写入。

## 实现摘要

- QQ 群入站消息在 OneBot 消息 ID 去重后写入公共群历史 session，session 使用非隔离语义：`qq-<botId>-group-<groupId>`。
- 开启群聊隔离时，bot LLM 上下文仍写入隔离 session：`qq-<botId>-group-<groupId>-user-<userId>`。
- 非隔离 LLM 路径复用公共群历史中已写入的用户消息，避免同一入站消息重复追加。
- `hostApi.conversation.history` 对 `group:<gid>` 和 `group:<gid>:user:<uid>` 优先映射到公共群 origin：`group:<gid>`，再回退到旧的精确 session / origin 查找。
- `hostApi.message.send` 和 message stream 的宿主侧持久化继续解析插件会话 ID 到真实 repository session，避免以 `group:<gid>:user:<uid>` 这类外部 ID 直接追加消息。
