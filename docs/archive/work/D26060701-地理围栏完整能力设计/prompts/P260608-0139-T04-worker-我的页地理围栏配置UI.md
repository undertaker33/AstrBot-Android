### Q1：缺少定位权限时仍可提交 ACTIVE enabled 规则

问题：

- `GeofenceRuleEditorDraft.toRule(...)` 对新建 enabled 规则直接给 `GeofenceRuleStatus.ACTIVE`。
- `GeofenceRulesScreen` 只展示权限状态，保存按钮或保存路径没有根据 `permissionStatus` 降级。
- 结果是前台/后台权限缺失时 UI 能保存“启用且 active”的规则，形成后台权限假象。

修复要求：

- UI 保存 enabled 规则时必须将当前 `GeofencePermissionStatus` 传入 draft/controller 保存路径。
- 缺 foreground 或 background 权限时，允许保存草稿/规则，但状态必须为 `PERMISSION_REQUIRED`，不得保存为 `ACTIVE`。
- 如果用户关闭 enabled，则状态应是 `PAUSED`。
- 补测试覆盖：
  - foreground/background 任一缺失时，enabled create/update 输出 `PERMISSION_REQUIRED`。
  - 权限完整且 enabled 时才输出 `ACTIVE` 或保留合理 active 状态。

### Q2：create/update/delete 失败被 UI 吞掉或失去一致状态

问题：

- 创建/编辑保存后立即关闭弹窗。
- ViewModel 只写 `RuntimeLogger`，没有把失败回流到页面。
- 删除确认也先关闭状态；仓储可能抛出校验或引用错误。

修复要求：

- ViewModel 增加 UI 操作错误状态，例如 `operationErrorState` / `snackbarMessage` / `dialogErrorMessage`，并在 create/update/delete/pause/resume/listRuns 失败时回流。
- create/update 失败时不要假装成功；至少要保留可见错误提示。若要关闭弹窗，页面必须仍有错误提示；更推荐保存成功后再关闭。
- delete 失败时必须显示错误，不要只清空确认状态。
- 补测试覆盖：
  - create/update repository 抛错时错误状态可观察。
  - delete 抛错时错误状态可观察。
  - 成功后错误状态清除。

### Q3：已删除/不存在的 bot target 仍可能被 enabled 编辑提交

问题：

- UI 在 `selectedBotId` 非空但不在 `botProfiles` 中时构造 synthetic `BotProfile`。
- draft 只校验 target 字段非空，导致编辑旧规则时 stale bot target 可以继续作为 enabled 规则保存。

修复要求：

- enabled 保存必须要求 `selectedBotId` 存在于当前 `botProfiles`。
- 不得为 enabled 保存构造 synthetic `BotProfile`。如果旧规则的 bot 不存在，应阻断提交并显示 target error；disabled 草稿可保留字段但不能启用提交。
- 补测试覆盖 stale bot：
  - selectedBotId 不在 botProfiles 中时，enabled 规则不能提交。
  - UI/handler 不调用 repository 保存。
