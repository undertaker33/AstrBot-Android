## 必须修复

1. DAO transaction 原子性

   当前 `FeatureGeofenceRuleRepositoryStore.createRule()` 和 `replaceRegions()` 的 rule/regions 写入不在同一个 Room transaction。失败或取消会留下半更新。

   要求：

   - 下沉为 DAO 级 `@Transaction` 聚合写入方法，例如 `upsertRuleWithRegions()`、`replaceRegionsAndTouchRule()`。
   - store 使用这些事务方法。
   - 测试覆盖 create/replace 的生产语义。

2. 引用完整性

   当前 `geofence_regions`、`config_geofence_bindings`、`geofence_execution_records` 缺少 FK；store 也可能写入不存在的 rule/config/region 引用。

   要求：

   - 对 owned children 使用 Room FK cascade，或在 repository 写入口显式检查父记录。
   - 至少 `geofence_regions.ruleId -> geofence_rules.ruleId` 和 `config_geofence_bindings.ruleId -> geofence_rules.ruleId` 要能防止孤儿数据。
   - `geofence_execution_records` 如果要保留历史，可不要 cascade 删除，但必须明确防止明显无效引用或把快照语义落到模型/测试里。
   - 同步 migration、schema、schema contract 和真实 Room 测试。

3. Validation 补强

   当前 validation 未拒绝负数 `dwellDelayMillis`、`minimumTriggerIntervalMillis`，execution record 未校验时间字段。

   要求：

   - `dwellDelayMillis >= 0`
   - `minimumTriggerIntervalMillis >= 0`
   - 如果 `triggerDwell = true`，`dwellDelayMillis > 0`
   - execution record 时间字段不能明显非法：`startedAt >= 0`，`completedAt >= 0`，如果 completed 非 0 则不能早于 started。
   - 补 validation 测试。

4. 真实 Room / migration 测试

   当前测试过度依赖手写 fake，schema contract 只是 token 检查。

   要求：

   - 至少增加一个真实 Room in-memory DAO/store 测试，覆盖事务、FK/引用语义、排序。
   - 至少增加一个 `MigrationTestHelper` 的 23->24 migration case，覆盖 geofence 表创建和 migration validation。
   - 如果原 worker 已创建相关半成品，请完善并跑通，不要删除有效工作。
