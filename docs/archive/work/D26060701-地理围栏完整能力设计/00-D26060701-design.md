# D26060701 地理围栏完整能力设计

更新时间：2026-06-07 00:46 +08:00

## 1. 场景与目标

本任务包设计完整的“地理围栏”能力，而不是只设计触发配置。目标是在 ElymBot Android Native 内提供一个内部地理围栏系统：

1. 用户可以创建一个或多个地理围栏规则；每条规则可以包含一个或多个圆形位置范围，位置由经纬度和半径定义。
2. 用户可以通过两种模式创建地理围栏：
   - 手动创建：在“我的-地理围栏配置”二级页面中使用地图选择器、当前位置、经纬度输入和表单配置。
   - Agent 创建：用户用自然语言 prompt 描述目标，由 Agent 调用宿主内部工具创建或更新地理围栏。
3. 进入、离开或停留在范围内时，系统可以触发内部 Agent 能力：发送一条消息、推送天气预报、推送新闻/web search 摘要，或执行后续允许的宿主能力。
4. 地理围栏不作为对外插件 API 暴露。插件不能直接创建、读取、修改或触发地理围栏。
5. “我的-地理围栏配置”是地理围栏配置唯一真源；配置详情页只装载引用，不复制坐标、半径或动作定义。
6. 首次创建或启用需要地理位置权限；后台触发需要后台定位权限，并需要清晰的用户授权流程。
7. 在“配置-配置详情页-平台设置”增加“地理围栏”项，以弹窗方式管理当前 ConfigProfile 装载哪些已配置的地理围栏规则。

## 2. 当前仓库约束

现有事实：

- `:app` 负责 Manifest、Application、Activity、导航壳层、全局 top bar 和平台薄胶水。
- 生产依赖注入只能通过 Hilt，不恢复 static registry、service locator 或手写 runtime subgraph。
- `:feature:cron` 已有相近结构：`api/data/runtime/presentation`、Room 持久化、WorkManager/Hilt Worker、Me 入口、二级页、分页、FAB 创建弹窗、runtime reconciliation 和 Agent runtime 投递。
- `ConfigDetailScreen` 当前通过抽屉分组展示“平台设置”，白名单是 ConfigProfile 内字段；地理围栏不能照搬白名单内嵌列表，因为需求要求“我的-地理围栏配置”为唯一真源。
- 当前 Manifest 只有 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`、`POST_NOTIFICATIONS`、`INTERNET`、`REQUEST_INSTALL_PACKAGES`，没有定位权限。
- 当前仓库没有 `play-services-location` 或地图 SDK 依赖。

外部 Android 约束：

- Android Geofencing API 使用圆形地理围栏：纬度、经度、半径和 transition 类型。
- Google Play services `GeofencingClient.addGeofences(...)` 以 `PendingIntent` 接收 transition。
- Android 后台定位需要 `ACCESS_BACKGROUND_LOCATION`，且 Android 11+ 通常需要引导用户到系统设置页授权“始终允许”。
- Android 8+ 后台地理围栏触发存在延迟，不应承诺秒级触发；半径过小会带来抖动和误触发。
- Play services geofence 有数量上限，设计上按最多 100 个 active geofence 处理。

资料入口：

- Android Geofencing: <https://developer.android.com/develop/sensors-and-location/location/geofencing>
- Background location permission: <https://developer.android.com/develop/sensors-and-location/location/permissions/background>
- GeofencingClient: <https://developers.google.com/android/reference/com/google/android/gms/location/GeofencingClient>
- Maps SDK for Android: <https://developers.google.com/maps/documentation/android-sdk/overview>
- Maps Compose: <https://developers.google.com/maps/documentation/android-sdk/maps-compose>

Context7 说明：本轮已按项目规则尝试使用 Context7，但当前会话没有暴露 `resolve-library-id` / `query-docs` 可调用工具；因此本设计使用官方 Android / Google Developers 文档作为外部依据，不声称已由 Context7 返回资料。

## 3. 推荐架构

新增 feature-first 模块组：

```text
:feature:geofence:api
:feature:geofence:data
:feature:geofence:runtime
:feature:geofence:presentation
:feature:geofence:impl   # 可选聚合壳，不作为生产 owner
```

模块职责：

- `:feature:geofence:api`
  - domain model、repository port、runtime registration port、permission/status port、Agent 创建 port、地图选择 DTO。
  - 不依赖 Android UI、Room、Google Play services 或地图 SDK。
- `:feature:geofence:data`
  - Room-backed store、mapper、repository port adapter。
  - 拥有地理围栏规则、位置区域、Config 绑定和执行记录的数据真源。
- `:feature:geofence:runtime`
  - Google Play services `GeofencingClient` 注册/注销。
  - `BroadcastReceiver` 接收 transition。
  - Hilt Worker 执行触发、节流、Agent runtime 分发和执行记录。
  - 启动 reconciliation、权限状态检查和 Play services 可用性诊断。
- `:feature:geofence:presentation`
  - “我的-地理围栏配置”页面。
  - 地图选择器、当前位置选择、经纬度输入、规则列表、创建/编辑卡片、运行记录弹窗。
  - ConfigDetail 平台设置弹窗所需的可选列表 UI 或 presentation model。
- `:feature:geofence:impl`
  - 若创建，只作 `api + data + runtime + presentation` 聚合；不得写生产业务逻辑。

Hilt wiring：

- `app-integration` 绑定 repository、runtime reconciliation、permission/status、Agent tool facade。
- `:app` 只负责 Manifest 权限/receiver 壳层、导航 route 和启动链接入。
- 不新增 static registry，不让 Config UI 直接访问 DAO。

## 5. 地图选择器设计

地图选择器是手动创建模式的主要交互，不把经纬度手填作为唯一入口。

推荐实现：

- 主路径使用 Google Maps SDK + Maps Compose：
  - 地图展示当前选中点。
  - 点击地图移动圆心。
  - 拖动或点击后更新经纬度字段。
  - 半径用 slider + 数字输入双入口。
  - 地图上画圆形覆盖层，实时显示半径。
- 兜底路径：
  - 如果缺少 Maps API key、地图 SDK 不可用或设备环境不支持，则显示经纬度输入 + 半径输入 + “使用当前位置”按钮。
  - 兜底不阻断保存，只影响地图可视选择体验。
- 当前位置：
  - 仅在用户点击“使用当前位置”或首次创建需要当前位置时请求前台定位权限。
  - 获取当前位置失败时只提示错误，不自动写入空坐标。

依赖和配置：

- 地图 SDK key 不写入源码或 task doc；实现时通过 `local.properties`、manifest placeholder 或安全配置注入。
- 不把地图 SDK 放入 `:feature:geofence:api`；只放在 presentation 或 app shell 所需边界。

UI 细节：

- “位置”区域展示区域卡片列表，每个区域包含名称、地址标签、经纬度、半径。
- 每条规则可添加多个区域；FAB 创建规则时默认一个空区域。
- 地图选择弹窗/卡片支持：
  - 地图点选。
  - 使用当前位置。
  - 手填经纬度。
  - 半径 slider。
  - 地址标签手填；第一版不强制做反向地理编码。

## 6. 两种创建模式

### 6.1 手动创建模式

入口：

```text
我的 -> 地理围栏配置 -> 右下角 + -> 创建/编辑卡片
```

表单字段：

- 名称。
- 启用状态。
- 区域列表。
- 触发类型：进入、离开、停留。
- 停留延迟。
- 动作类型。
- 动作 prompt。
- 目标平台：App Chat / QQ OneBot。
- 目标会话。
- Bot、Config、Persona、Provider。
- 最小触发间隔。

保存行为：

1. 校验字段。
2. 如果需要当前位置或启用后台地理围栏，检查权限。
3. 保存到 Room。
4. 若 enabled 且权限满足，则调用 runtime registration 重新注册。
5. 若权限不足，保存规则但状态标为 `permission_required`，UI 引导授权。

### 6.2 Agent prompt 创建模式

用户可以在聊天中描述地理围栏，由 Agent 自动创建。示例：

```text
帮我创建一个地理围栏：名称“到公司提醒”，位置使用当前位置，半径 150 米，进入时发送消息到 App Chat：提醒我整理今天的待办。
```

```text
创建地理围栏“离开家查天气”：中心点 31.2304, 121.4737，半径 200 米，离开时查询当前位置未来 6 小时天气并推送摘要。
```

```text
新增地理围栏“到火车站看新闻”：经纬度 39.9022, 116.4279，半径 300 米，进入时使用 web search 获取本地交通/天气相关新闻，发到默认会话。
```

内部工具设计：

- 新增 host-owned tool source，例如 `GeofenceCapabilityToolSourceProvider`。
- 工具仅对宿主 Agent runtime 可见，不进入插件 Host API。
- 工具可包含：
  - `create_geofence_rule`
  - `update_geofence_rule`
  - `list_geofence_rules`
  - `delete_geofence_rule`
  - `pause_geofence_rule`
  - `resume_geofence_rule`
- 地理围栏 transition 触发的 Agent turn 默认不暴露创建/修改 geofence 的工具，避免自我递归创建。
- 如果 prompt 使用“当前位置”，但当前没有前台定位权限，工具返回 `permission_required`，由 UI 层发起权限申请；Agent 不能绕过系统权限。
- 如果 prompt 未给坐标、地址或当前位置，工具返回 `missing_location`，不猜测位置。

Agent 创建结果：

- 成功后返回规则名称、区域数量、触发条件、动作摘要、权限/注册状态。
- 若保存成功但后台权限不足，返回“已保存但未启用后台触发，需要授权”。

## 7. 权限流程

权限分层：

- 前台定位：`ACCESS_FINE_LOCATION`，可配合 `ACCESS_COARSE_LOCATION`。
- 后台定位：`ACCESS_BACKGROUND_LOCATION`。
- 通知：若动作包含本地通知，沿用 `POST_NOTIFICATIONS` 的现有授权姿态。

首次创建流程：

1. 用户点击“+”或 Agent 尝试创建需要当前位置/启用 geofence。
2. UI 先解释用途：用于用户配置的地理围栏 enter/exit/dwell 触发。
3. 请求前台定位权限。
4. 如果用户启用后台触发，再解释后台定位用途，并引导到系统设置授予后台定位。
5. 权限不足时允许保存草稿，但不注册 active geofence。

实现原则：

- 不在 app 启动时主动请求定位权限。
- 不把地理围栏与 NapCat/容器权限混淆，不新增任何存储权限。
- 权限状态是 runtime status，不写成规则内容本身。

## 8. 运行时注册与触发

### 8.1 注册

新增 `GeofenceRuntimeReconciliationPort`：

- app 启动时从 `RuntimeLaunchStartupChain` 调用 `reconcileAsync(appScope)`。
- 权限变化、规则保存、规则暂停/启用、Config binding 变化后触发重注册。
- 只注册 enabled 且有至少一个 enabled config binding 的规则；若设计要求未绑定也可运行，则必须使用规则自身 target config，但本设计默认“装载后运行”。
- 总 active region 超过 100 时，按规则 `updatedAt` 或显式优先级截断，并把被跳过规则标为 `registration_failed` / `capacity_exceeded`。

### 8.2 Receiver 与 Worker

Manifest 增加非导出 receiver：

```text
GeofenceTransitionReceiver
```

流程：

1. `GeofencingClient` 通过 immutable `PendingIntent` 投递 geofence transition。
2. Receiver 解析 transition 和 triggering geofence ids。
3. Receiver enqueue `GeofenceTransitionWorker`，不在 receiver 中做网络、LLM 或数据库重操作。
4. Worker 读取规则、区域、Config binding，写 execution start record。
5. Worker 做节流、权限/状态复核和动作分发。
6. 完成后写 execution complete record。

### 8.3 触发动作

动作执行分三类：

- `send_message`
  - 直接构造消息并通过宿主投递 port 发到 App Chat / QQ。
- `agent_prompt`
  - 复用现有 `RuntimeLlmOrchestratorPort`，构造 `RuntimeIngressEvent`。
  - 建议新增 `IngressTrigger.GEOFENCE_EVENT`；如果短期不扩 enum，则 raw payload 必须明确 `trigger = geofence_event`，但更推荐扩 enum。
- `weather_forecast` / `news_digest`
  - 本质仍是 agent prompt，只是预置 prompt 模板并要求目标 ConfigProfile 开启 web search。
  - 如果目标 config 未开启 `webSearchEnabled`，UI 应警告；运行时不绕过 config 策略。

触发 payload 应包含：

- `ruleId`
- `ruleName`
- `regionId`
- `regionLabel`
- `transition`
- `latitude`
- `longitude`
- `radiusMeters`
- `occurredAt`
- `configId`

## 9. Config 装载设计

配置详情页新增：

```text
配置 -> 配置详情 -> 平台设置 -> 地理围栏
```

交互：

- 在平台设置抽屉分组中新增 `ConfigSection.Geofence`。
- Section 内显示当前已装载数量和前 2 个规则摘要。
- 点击“管理”打开弹窗。
- 弹窗通过下拉框或多选列表选择“我的-地理围栏配置”中已存在的规则。
- 支持启用/禁用当前 config 对某条规则的装载。
- 不允许在这里编辑坐标、半径或动作 prompt；只提供跳转到“我的-地理围栏配置”的入口。

保存模型：

- `ConfigProfile` 不新增坐标、半径、动作 prompt 字段。
- 建议不要把 geofence binding 放进 `ConfigProfile` 主字段，避免 ConfigProfile 膨胀；使用 `config_geofence_bindings` 独立表。
- `ConfigViewModel.saveWithResourceProjections(...)` 不承载 geofence binding；新增专门的 geofence binding port 或 presentation controller。

## 11. 与插件边界

明确不暴露：

- 插件 Host API 不新增 `hostApi.geofence.*`。
- 插件不能读取用户地理围栏规则、坐标或执行记录。
- 插件不能注册 geofence transition handler。
- Geofence transition 不作为 Plugin V2 scheduled handler 直接触发来源。

可以复用：

- Agent runtime 内部已有 ToolSource / LLM orchestration / delivery 能力。
- 运行时可以触发宿主内部 Agent 能力，而不是让插件接管地理围栏。

如果未来需要插件参与，必须另开设计，至少要有权限审计、坐标隐私保护、触发授权白名单和用户可撤销开关。本任务包不做。

## 12. 备份与隐私

隐私：

- 经纬度、地址标签和触发记录属于敏感数据。
- UI 应明确这是本地配置的地理位置数据。
- 日志不输出完整经纬度；运行日志仅输出 ruleId、regionId、transition 和粗略状态。
- execution record 可保存位置快照，但不应进入普通 runtime log 明文。

备份：

- 第一版建议不把 geofence 纳入 full backup restore 的 supported 范围，先在 `BackupParticipantRegistry` 标为 `PLANNED` 或不纳入。
- 如果用户要求完整备份能力，则必须单独设计：
  - 是否导出坐标。
  - 是否导出执行历史。
  - 恢复后是否自动启用。
  - 恢复后是否必须重新请求权限。
- 本设计默认：规则数据可后续支持备份；执行历史不备份。

## 13. 错误处理与状态

常见状态：

- `permission_required`：规则已保存，但缺前台或后台定位权限。
- `play_services_unavailable`：设备无可用 Play services geofencing。
- `registration_failed`：注册失败。
- `capacity_exceeded`：active region 超过上限。
- `invalid_region`：坐标或半径无效。
- `throttled`：触发过于频繁，被最小间隔拦截。
- `delivery_failed`：Agent 或消息投递失败。

UI 展示：

- 规则卡片显示状态标签。
- 运行记录弹窗显示错误 code、时间和摘要。
- 权限不足时给出明确行动入口，不把错误藏在日志里。

  - 经纬度、半径、trigger、动作字段校验。
- `GeofenceRuntimeRegistrationTest`
  - enabled + binding 才注册。
  - 权限不足不注册。
  - 超过 100 active region 的处理。
- `GeofenceTransitionWorkerTest`
  - enter/exit/dwell 解析。
  - 节流。
  - execution record start/complete。
  - action prompt payload。
- `GeofenceAgentToolSourceProviderTest`

  - 缺位置返回 `missing_location`。
  - 缺权限返回 `permission_required`。
  - geofence-triggered turn 不暴露 create/update 工具。

  - 一页 2 项分页。
  - FAB 创建。
  - 地图兜底输入。
  - ConfigDetail 管理弹窗只保存 binding。
- 架构合同：
  - `:feature:geofence:api` 不依赖 Android / Room / Google Play services。
  - plugin API 不出现 geofence host API。
  - app 不直接依赖 geofence data/runtime implementation，生产 wiring 走 app-integration + Hilt。

## 16. 当前设计决策

- 决策 1：新增完整 `feature/geofence` 模块组，而不是把地理围栏塞入 Cron、Settings 或 Config。
- 决策 2：“我的-地理围栏配置”为唯一真源，ConfigDetail 只存 `config_geofence_bindings` 引用。
- 决策 3：支持两种创建模式：手动 UI + Agent prompt 内部工具。
- 决策 4：地图选择器为主体验，但必须有经纬度/当前位置兜底。
- 决策 5：地理围栏不暴露插件 API。
- 决策 6：运行时采用 Google Play services Geofencing API；不以持续位置轮询作为第一版主线。
- 决策 7：天气/新闻是 geofence action 的 Agent prompt 模板，不绕过 ConfigProfile 的 web search 策略。

## 17. 残余风险

- Android 后台 geofence 触发不是实时能力，可能存在分钟级延迟。
- Android 11+ 后台定位授权流程依赖系统设置页，用户可能拒绝。
- 无 Google Play services 的设备需要明确降级状态；若必须支持这类设备，需要另设自研低频定位轮询方案。
- 地图 SDK API key 和网络可用性会影响地图选择器，但不应影响经纬度手动创建。
- 真实厂商 ROM 可能限制后台广播/worker，必须做真实设备验收。
- 坐标属于敏感数据，日志、备份和插件边界必须严格。

## 18. 设计自检

- 无开放用户问题：用户已确认完整地理围栏设计、两种创建模式、地图选择器和无需确认则写 Design。
- 无源码改动：本 Design 不实现代码。
- 无 ADR 写入：本任务是单任务范围设计，虽包含模块边界决策，但尚未进入长期 ADR 记录门槛；如后续决定“所有宿主主动触发能力统一抽象为 ActiveCapability”再考虑 ADR。
- `Needs uth-docs scoped-sync`：后续实现完成并验证后，需要同步 `docs/context/02`、`03`、`06`、`10`、`11`，并可能新增 geofence 模块上下文。
