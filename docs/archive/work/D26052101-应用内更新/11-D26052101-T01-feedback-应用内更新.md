## 原始需求

新增应用内更新功能：应用每次打开时检测一次项目 GitHub Release 页 latest APK；有更新时在应用内弹窗提示，用户必须在 `更新`、`暂不更新`、`忽略此版本` 中三选一；`暂不更新` 隔一天再弹，`忽略此版本` 只忽略当前 release；debug 包下载 debug APK，release 包下载 release APK；下载时显示进度条，下载完成后提示安装，点击后以系统默认方式打开 APK，安装完成后自动清理安装包。

## 实现摘要

- 新增 `com.elymbot.android.update` 应用更新主线，包含 release 查询、版本判断、asset 选择、tag-scoped 本地抑制、下载状态、安装 Intent 和安装后清理。
- `MainActivity` 接入 `AppUpdateViewModel.checkForUpdateOnce()` 与 `AppUpdateDialogHost`，并保持插件 deep link 确认弹窗优先，避免两个 modal 叠加。
- Manifest 新增 `REQUEST_INSTALL_PACKAGES`、应用更新 `FileProvider` 与 `MY_PACKAGE_REPLACED` cleanup receiver；新增 `@xml/update_file_paths`。
- 下载主线新增 `DownloadOwnerType.APP_UPDATE`，网络模型新增 `RuntimeNetworkCapability.APP_UPDATE` 与 `RuntimeTimeoutProfile.APP_UPDATE`。
- 弹窗状态覆盖初始三选一、下载进度、准备安装和失败态；所有更新弹窗禁止点击外部关闭，失败态提供 `重试`、`暂不更新`、`忽略此版本`。
- 修复 worker 初版中 `BuildConfig` 可用性问题，改为注入 `AppUpdateBuildInfo`，便于测试 debug/release track。

## 风险与回滚

- 若安装 Intent 在某些 ROM 上不能直接拉起系统安装器，可在后续 `uth-debug` 中评估 `ACTION_INSTALL_PACKAGE` fallback。
- 若 GitHub release asset 命名偏离 `debug` / `release` 约定，应用将按设计跳过提示而不是下载错误 track 包。
- 回滚本功能应同时移除 app update 包、Manifest provider/receiver/permission、`APP_UPDATE` download/network 枚举、MainActivity host 接入和对应测试。
