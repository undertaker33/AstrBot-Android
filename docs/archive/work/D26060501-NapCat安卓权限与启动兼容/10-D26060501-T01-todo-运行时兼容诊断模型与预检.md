## 目标

建立第一层诊断能力，让后续启动流程能区分：

- rootfs 缺失
- native runtime link 缺失
- app 私有目录 / proot 执行受限
- `/sdcard` 不可读或不可绑定
- 通知权限拒绝但不阻断
- 未知 ROM / proot 失败

本 Todo 不负责把诊断接入 `ContainerBridgeService` 的启动决策；接入放到 T03。

## 必须实现

1. 新增诊断分类模型
   - 建议命名：`RuntimeCompatibilityCategory`
   - 至少覆盖 `READY`、`ROOTFS_MISSING`、`NATIVE_RUNTIME_MISSING`、`APP_PRIVATE_EXEC_RESTRICTED`、`PROOT_SMOKE_FAILED`、`EXTERNAL_STORAGE_BIND_SKIPPED`、`NOTIFICATION_PERMISSION_DENIED`、`UNKNOWN`
   - 每个结果必须有 `blocking`、`userMessage`、`technicalDetails`

2. 新增诊断 snapshot
   - 建议命名：`RuntimeCompatibilitySnapshot`
   - 包含 SDK、manufacturer、model、target SDK、app home、native library dir、rootfs/proot/loader/script 检查状态、external storage 可读性、通知权限状态
   - snapshot 只用于日志和状态展示，不持久化

3. 新增 preflight owner
   - 建议命名：`RuntimeCompatibilityProbe`
   - 通过 Hilt constructor injection 提供依赖
   - 不直接依赖 QQ data 或 presentation
   - 可通过注入 seam 模拟 `Build.VERSION.SDK_INT`、文件系统、权限状态和 smoke command

4. 单元测试覆盖分类
   - rootfs 缺失 -> blocking `ROOTFS_MISSING`
   - proot/loader 缺失 -> blocking `NATIVE_RUNTIME_MISSING`
   - smoke stderr 包含 `Permission denied` -> blocking `APP_PRIVATE_EXEC_RESTRICTED`
   - smoke 非 0 但不是权限关键字 -> blocking `PROOT_SMOKE_FAILED`
   - `/sdcard` 不可读 -> non-blocking `EXTERNAL_STORAGE_BIND_SKIPPED`
   - Android 13+ 通知权限拒绝 -> non-blocking `NOTIFICATION_PERMISSION_DENIED`
