## 目标

完成用户可见的兼容闭环：

- `ContainerBridgeService` 在真正 `startNapCat()` 前运行 T01 preflight。
- blocking 诊断阻断启动并 `markError(...)`。
- non-blocking 诊断写入日志和 progress/details 后继续启动。
- `AndroidRuntimeBridgeController` 将 foreground service 启动异常分类写入 runtime logger。
- Android 13+ 通知权限拒绝不阻断启动，但状态可解释。
- Android 14+ 前台服务类型语义与 manifest 保持一致。
- 完成本任务包回归 gate，并标记后续 `uth-docs scoped-sync`。

## 必须实现

1. preflight 接入启动链
   - `ContainerBridgeService.handleStartBridge()` 在 `containerRuntimeInstaller.ensureInstalled()` 之后、`containerRuntimeController.startNapCat()` 之前运行 probe
   - blocking 结果调用 `bridgeStatePort.markError(snapshot.userMessage)`，追加 `technicalDetails` 到 `RuntimeLogger`，不调用 `startNapCat()`
   - non-blocking 结果记录 logger，并通过 progress/details 呈现，不阻断启动

2. foreground service 启动异常分类
   - `AndroidRuntimeBridgeController.startService(...)` 对 `SecurityException`、foreground service start exception、普通 service start exception 做不同日志文案
   - Android O+ 继续使用 `startForegroundService`
   - 非 foreground stop/check 行为不应被破坏

3. Android 14+ data sync 类型确认
   - 保持 manifest 中 `FOREGROUND_SERVICE_DATA_SYNC` 和 `foregroundServiceType="dataSync"`
   - 如实现中使用兼容库或平台 API 显式传入 data sync type，必须保持旧版本兼容
   - 如果无法安全改运行时 API，只通过合同测试和日志确认 manifest 类型，不做冒险变更

4. 用户可见状态
   - `Permission denied` 必须被映射到具体失败点
   - 通知权限拒绝不得阻断启动
   - 外部存储 bind skipped 不得显示为安装失败
   - 网络 installer 失败仍保留现有 progress label 语义

5. 包级回归
   - 本 Todo 是 D26060501 的 Design-level 前最后开发切片，完成后必须运行稳定节点或明确记录未覆盖项
