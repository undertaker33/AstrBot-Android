> **For agentic workers:** Use `uth-sp-subagent-driven-development` or `uth-sp-executing-plans` only if the owning UTH scene chooses that execution mode. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce Gradle configuration hotspots and make the app unit-test task graph explicitly governed instead of continuing to grow as a whole-repo classpath.

## 目标

治理 Design 中风险更高的构建脚本热点：

- 根 `build.gradle.kts` 中 module group 任务不再依赖全局 `gradle.projectsEvaluated`。
- `app/build.gradle.kts` 的 APK export finalizer 不再使用 `afterEvaluate`。
- `:app:testDebugUnitTest` 的手工 runtime project / friend-path 列表改为按测试域命名的显式集合，为后续迁移和收窄提供边界。

## 已确认约束

- 不删除 module group 任务。
- 不删除 `architectureCheck` 依赖，也不缓存 architecture 报告任务。
- 不改变 APK 导出目录：`artifacts/apk/<branch>/<variant>`。
- 不大规模迁移测试源码归属。
- 不靠继续扩大 `-Xfriend-paths` 解决测试可见性问题。
- 不执行 Git 写入。

## 非目标

- 不升级 Gradle、AGP、Kotlin、KSP、Hilt 或 AndroidX。
- 不引入新 Gradle 插件。
- 不删除 `clean assembleDebug` 验收要求。
- 不修改业务生产源码。
- 不更新 `docs/context/`；实现完成后只标记是否需要 `uth-docs scoped-sync`。

## 必须实现

1. module group lazy wiring
   - 删除全局 `gradle.projectsEvaluated` 块。
   - 使用 `plugins.withId("com.android.application")` / `plugins.withId("com.android.library")` 为 module group build task 绑定 `assembleDebug`。
   - 为 module group check task 保留对各模块 `check` 的依赖。
   - 如果遇到非 Android 模块，显式绑定其 `assemble` 或证明它不在 module group 内。

2. app APK export finalizer
   - 移除 `app/build.gradle.kts` 中的 `afterEvaluate`。
   - 保持 `assembleDebug` / `assembleRelease` 完成后运行对应 `export*ApkByBranch`。

3. app unit-test task graph governance
   - 将 `appUnitTestRuntimeProjects` 拆成按测试域命名的集合，例如 app shell、plugin host、QQ、cron、core runtime、feature data。
   - 将 `compileDebugUnitTestKotlin` 的 friend paths 拆为同样的命名集合。
   - 不删除无法证明安全的 runtime project；第一轮目标是让列表显式可治理。

## 执行步骤

- [x] **Step 1: 替换 module group 后置解析**

在 `build.gradle.kts` 中把每个 module group task 注册后，立即通过子项目插件回调绑定对应 build/check 任务；删除 `gradle.projectsEvaluated`。

- [x] **Step 2: 替换 APK export afterEvaluate**

在 `app/build.gradle.kts` 中改用可验证的 lazy task wiring，确保 `assembleDebug` / `assembleRelease` 仍 `finalizedBy(export*ApkByBranch)`。

- [x] **Step 3: 分组 app 单测 runtime/friend path**

保留当前测试能运行的依赖集合，但改成命名分组，避免后续新增模块继续无边界追加到一个全仓列表。

- [x] **Step 4: 运行验证**

执行：

```powershell
.\gradlew.bat modulePluginCheck moduleQqCheck --configuration-cache --console=plain --no-daemon --stacktrace
.\gradlew.bat :app:testDebugUnitTest --dry-run --configuration-cache --console=plain --no-daemon --stacktrace
.\gradlew.bat architectureCheck --configuration-cache --console=plain --no-daemon --stacktrace
.\gradlew.bat clean assembleDebug --console=plain --no-daemon --stacktrace
```

预期：命令退出码为 0；module group 任务仍能解析；APK export finalizer 未改变产物目录；app unit-test dry-run 的任务图保持可解释。

记录变更文件、验证命令、结果、未覆盖项、风险与回退，并把 `docs/current-state.md` 中 `D26060301` 状态更新为 T02 已完成或阻塞。
